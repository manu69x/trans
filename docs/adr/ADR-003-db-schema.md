# ADR-003 · Final database schema (migration 001 / Alembic)

- **Status:** ACCEPTED
- **Date:** 2026-09-02
- **Phase:** F0 (discovery)
- **PRD refs:** §5.3 (structure), §5.4 (chunking), §6.2–6.6 (entities/glossary), §7.2 (TM), §8 (LLM), §13/§16 (audit/roles)

## 1. Context

PRD §6.5 only provides an *essential schema* (`projects`, `entities`,
`entity_aliases`, `entity_evidence`, `glossary_terms`, `translation_units`)
with UUID primary keys and no indexes, no binding explicit FKs, no TM table
with embeddings, and no support for structuring, LLM traceability, a job
queue or access control.

This ADR fixes the full schema, its location (Alembic migrations) and the
delta versus the PRD.

## 2. Decision

- **Alembic as the only migration engine.** The schema lives in
  `backend/migrations/versions/` as Alembic revisions (autogenerated from
  the ORM metadata). Rationale: reproducible versioning, possible
  downgrades, coherence with the FastAPI/SQLAlchemy stack of PRD §4.2. The
  backend container applies `alembic upgrade head` at boot — a fresh db
  volume needs no init SQL.
- **PostgreSQL 16 + pgvector as the only storage engine.** All embedding
  columns use the native `vector(768)` type (the `vector` extension is
  created per-connection in `migrations/env.py`). Rationale: native semantic
  retrieval (§7.2) with no conversions.
- **Native PostgreSQL `UUID`.** The PRD uses UUID PKs; we use the native
  `UUID()` type (not `as_binary`, which requires SQLAlchemy ≥ 2.1; the
  project pins `>=2.0`). Rationale: compatibility plus optimised btree
  storage/indexing.
- **`TIMESTAMP(timezone=True)` for every timestamp.** Equivalent of the
  PRD's `TIMESTAMPTZ` in SQLAlchemy 2.0; the DB stores UTC.
- **Explicit indexes on every FK and search field.** The PRD §6.5 declares
  none; here every join/filter column gets an `Index(...)` (`status`,
  `project_id`, `entity_type`, `source_normalized`, ...). Rationale: the
  retrieval queries (§7.2) and CAT joins are the core of the system —
  without indexes they degrade to O(n).
- **`render_as_batch=True`.** Every `create_table`/`drop_*` is wrapped in
  `batch_alter_table`. Rationale: idempotent DDL on Postgres, safe
  re-application.
- **JSONB for structural metadata.** `detection_method`, `terms_used`,
  `forbidden_targets`, `permissions`, `payload`/`result` (jobs),
  `before`/`after` (audit) are JSONB. Rationale: flexibility for
  parser/LLM-derived fields (§5.3, §7.2) without a rigid schema per
  evolution.

## 3. Schema (ER diagram)

```
projects (1) ──< structure_nodes (N)
                  ├─ parent_id → structure_nodes.id (self-referencing)
                 │
                 ├─< entities (N)        ──> entity_aliases (N)
                 │                          ──> entity_evidence (N)
                 │
                 ├─< glossary_terms (N)
                 │
                 ├─< translation_units (N)   (glossary_snapshot_id, tm_snapshot_id, model_run_id)
                 │
                 ├─< tm_entries (N)          (source_embedding vector(768))
                 │
                 ├─< llm_runs (N)
                 ├─< memory_snapshots (N)
                 ├─< jobs (N)
                 ├─< audit_log (N, project_id optional)
                 └─ users/roles are global (per-project via audit_log.user_id)

entities (1) ──< entity_aliases (N)
        (1) ──< entity_evidence (N)
```

Legend: `(1)` mandatory, `(N)` many. Every table has an `id UUID` PK and
`created_at` (plus `updated_at` where mutable). CASCADE deletions propagate
project removal to children.

| Table | Purpose (PRD) | Key fields |

| `entities` | §6.4/§6.5 | project_id, canonical_source/target, entity_type, referential_gender(+evidence), italian_grammatical_gender, grammatical_number, translation_policy, definition, notes, status, confidence, created/updated |
| `entity_aliases` | §6.5 | entity_id, source_alias, target_alias, alias_type (UNIQUE(entity_id,source_alias)) |
| `entity_evidence` | §6.5 | entity_id, chapter_id, source_segment_id, page_number, quote_text, evidence_type, confidence, extractor |
| `glossary_terms` | §6.5/§7.1 | project_id, source/target_term, term_type, preferred(bool), forbidden_targets[] (JSONB), grammatical_gender_it/number, inflection/usage_notes, status, version(INT) |

LLM run ref/branching (007), entity workflow (008), model settings (009),
TM↔segment links (011), immutable translation-unit **versions** (012), QA
issue fields (013/014), QE score columns (016), stable segment `numero`
(017), `is_english` score (018).

## 4. Delta vs PRD §6.5

| Element | PRD §6.5 | ADR-003 | Why |
|---|---|---|---|
| Tables | 6 | + `structure_nodes, tm_entries, llm_runs, memory_snapshots, jobs, audit_log, users, roles` (14) | §5.3/§7.2/§8/§16 require structuring, TM with embeddings, LLM traceability, a queue, audit, roles |
| `entities.referential_gender` | present | + `referential_gender_evidence` | §6.4 demands proof + confidence for referential gender |
| Indexes / FKs | none declared | CASCADE FKs + index on every FK/search field | referential integrity and retrieval performance (§7.2) |
| `translation_units` | UNIQUE(project_id,chapter_id,ordinal) kept | same + status/project_id indexes | ordinal coherence + fast per-chapter queries |
| `tm_entries` | absent | present with `source_embedding vector(768)` | semantic retrieval is mandatory (§7.2) |
| `projects.genre_profile` | NOT NULL | same | genre profile required by §9/§12.2 |
| Glossary versioning | `version INT` present | same | kept as per PRD |
| Keys | UUID | native PostgreSQL UUID | SQLAlchemy 2.0 compatibility (see §2) |
| Timestamps | TIMESTAMPTZ | TIMESTAMP(timezone=True) | SQLAlchemy 2.0 equivalent (see §2) |

## 5. Verification

- `alembic upgrade head` applies cleanly on local PostgreSQL 16 with the
  `vector` extension.
- All six PRD §6.5 tables plus the eight additional ones are present; every
  §6.5 field is mapped (see §3.1).
- `tm_entries.source_embedding` is `vector(768)`; the extension is active.

Useful commands (from `backend/`):

```bash
export ALEMBIC_SQLALCHEMY_URI="postgresql://trans:trans@127.0.0.1:5432/trans"
alembic --config alembic.ini upgrade head     # apply
alembic --config alembic.ini upgrade -1       # rollback one step
alembic --config alembic.ini heads            # queue head
```

## 6. Alternatives considered

- **Hand-written DDL in an init SQL file:** rejected — not versioned, no
  downgrade path; the PRD stack calls for Alembic migrations.
- **`as_binary=True` for UUIDs:** rejected (requires SQLAlchemy ≥ 2.1); the
  project pins `>=2.0`.
